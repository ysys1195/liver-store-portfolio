### CTA状態

販売中:

```text
[ カートに追加 ]
```

Pending:

```text
[ 追加中... ]
```

販売前:

```text
[ 9/10 18:00 販売開始 ]
```

売り切れ:

```text
[ SOLD OUT ]
```

### 在庫表示状態

- 初回取得中はSkeletonとスクリーンリーダー向けLoading文言を表示する
- 取得成功時は最新の在庫数と販売状態、手動の「在庫を更新」を表示する
- 商品なし（404）と一時的な取得失敗を別の文言で表示する
- 自動Retry後も失敗した場合は「もう一度試す」で手動refetchできる
- stale状態で画面へ戻った場合はバックグラウンドで最新在庫を再取得する
- 再取得した在庫数・販売状態は販売状態バッジ、CTA、数量上限にも反映する
- 初回Loading中または最終取得失敗時はカート追加操作を表示しない

## 7. カート `/cart`

```text
+------------------------------------------+
| CART                                     |
|                                          |
| 商品A  ¥1,000  [-] 1 [+]  [削除]        |
| 商品B  ¥1,500  [-] 1 [+]  [削除]        |
|                                          |
| 小計 ¥2,500                              |
| [ 購入手続きへ ]                         |
|                                          |
| ※実際の決済は行われません               |
+------------------------------------------+
```

Empty State:

```text
カートは空です

[ 商品を見る ]
```

- カートはクライアントで安全にhydrateした後に表示する
- 商品詳細とカートの数量増加ボタンは、商品詳細表示時の在庫数に達した時点でdisabledにする
- 数量上限はZustand store側でも適用し、保存データ復元時の上限超過も補正する
- 商品詳細の追加可能数は在庫数からカート内の数量を差し引く。復元完了まで数量・追加操作を無効化し、残り0点では「在庫上限に達しています」と表示する。成功案内は実際に数量が増えた場合に表示する
- カートの表示価格・在庫は確定値ではなく、実注文時にはサーバーで再検証する
- カート表示時に最新在庫を取得し、0点となった商品はカートから自動削除する
- 自動削除後は「対象の商品が在庫切れとなったため、カートから自動で削除されました」と対象商品名を赤文字で表示する
- 通知は赤枠・薄赤背景でひとまとまりにし、テキスト直後の「×」で閉じられるようにする。閉じるまでは同じタブの再読み込み後も表示する
- 在庫取得に失敗しただけでは商品を自動削除しない

## 8. Demo Checkout `/checkout`

```text
+------------------------------------------+
| Portfolio Demo                           |
|                                          |
| 商品・数量・最新在庫                     |
| [ デモ注文を確定する ]                   |
| 成功: 注文番号・確定金額                 |
| 実際の注文・決済は行われません。         |
|                                          |
| [ TOPへ戻る ]                            |
+------------------------------------------+
```

- カートから移動し、確定ボタンでデモ注文APIを呼ぶ。表示だけでは注文しない
- pending中は「注文を確認中…」とdisabledを表示する
- 409時はエラーと再取得した在庫を表示し、カートへ戻れる
- 通信失敗や5xxでは「同じ注文キーで結果を再確認」を表示する。内容を変更して無条件に再送しない
- 成功時は注文番号・DB価格からの確定金額を表示する。再読み込み後も成功画面を復元する
- 空カートは送信不可。保存機能の利用不可・保存情報の破損時も送信を止める
- 実際の注文・決済が発生しないこと、非公式・非商用であることを確定前に表示する

## 9. Flash Sale Simulation `/demo/flash-sale`

```text
+------------------------------------------+
| FLASH SALE SIMULATION                    |
|                                          |
| Product: Birthday Goods                  |
| Initial Stock: 5                         |
| Concurrent Requests: 20                  |
|                                          |
| [ Reset ] [ Run Simulation ]             |
|                                          |
| Requests          20                     |
| Success            5                     |
| Conflict          13                     |
| Duplicate          2                     |
| Remaining Stock    0                     |
+------------------------------------------+
```

### Checkoutの通信待機・操作表示

- 注文mutationは`networkMode: always`とし、オフラインで待機した注文をオンライン復帰時に自動送信しない。通信失敗時は同じキー・内容での手動再確認を案内する。
- 注文リクエストはレスポンス本文の取得まで含めて15秒でタイムアウトし、fetchをabortする。これはサーバー側の注文取消を意味しないため、キーを保持し結果不明として扱う。
- 在庫refetchは注文mutationの完了を待たせず、独立したQueryでloading・errorを表示する。再取得失敗時は保存済みの古い在庫を「最新」と表示せず、手動再取得を表示する。
- 確定ボタンは有効時にホバーで色を変え、ポインターを表示する。無効時は薄く表示し、禁止カーソルにする。キーボード操作時にはフォーカス枠を表示する。
